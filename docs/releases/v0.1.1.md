## nocdeck 0.1.1 — add a device, with a username and a password

This release is the answer to the question the first release left open: *how does a
person actually add a device — an address, a port, a username and a password — without
a shell?* Both front doors now have a form, and the credentials that form takes are real
SNMPv3 credentials, not a field nobody could use.

### Added

- **SNMPv3, implemented here.** The User-based Security Model from RFC 3414, in the
  standard library:
  - engine discovery, and re-discovery when a device reboots between two polls;
  - authentication with HMAC-MD5-96, HMAC-SHA-96 and the SHA-2 family (RFC 7860):
    SHA-224, SHA-256, SHA-384, SHA-512;
  - privacy with AES-128-CFB (RFC 3826) and CBC-DES (RFC 3414 §8), per-message salts,
    and the 150-second timeliness window;
  - a new `crypto.py` (AES-128/192/256 and DES, written out in Python) checked against
    the FIPS-197 and NBS vectors and cross-checked against `openssl`;
  - the password-to-key algorithm pinned against the RFC's own `maplesyrup` samples in
    the test suite — a wrong megabyte of repetition produces a perfectly plausible wrong
    key that looks exactly like a mistyped password, so it is worth a test.
- **An add-device form.** The desktop window has `add device` (`Ctrl+N`) with a
  test-connection button; the web dashboard has `/add` with the same fields and the same
  button. `nocdeck add` gained `--user --auth --auth-key --priv --priv-key --context
  --keys-are-hex`.
- **One set of rules for all three.** `Device.validate()` is what the form, the dialog and
  the command line ask: an address is required, a port is a port, v3 needs a username,
  privacy needs authentication, and a passphrase can be an already-localised key in hex
  if that is what your change management hands out.
- **`edit` and `remove` in the desktop window**, and a remove button in the web
  dashboard. Deleting asks twice and takes the history with it.
- **The demo's firewall speaks v3** — polled through the real USM code, over a loopback
  socket, so nothing in the demo can succeed by accident.
- **`nocdeck doctor`** now runs the v3 crypto self-test and checks every device record
  against the same validation rules.

### Changed

- The v1/v2c decoder no longer claims v3 is unimplemented: it points at the module that
  reads v3, which is now a module.
- `nocdeck show --json` and the whole web API return `public_dict()`: which credentials
  are set, never what they are.
- An integer with the INTEGER tag may be negative. An SFP reporting −6.50 dBm is a working
  optic, and the encoder refused to write one.
- `nocdeck version` and `doctor` report v1/v2c/v3 rather than v1/v2c.

### Fixed

- **The dashboard's JavaScript did not parse.** A malformed `.finally(…)` took the live
  refresh, the clock and the poll buttons down with it, silently. There is a stylesheet
  typo fixed alongside it, and both are the kind of thing only a browser console says.
- The v1/v2c encoder wrote every integer unsigned, so a signed metric could not be
  encoded at all.
- **`_ProbeWorker` / test-connection** polls without writing: a device that was only being
  tried out no longer lands in the inventory or in the history of a device that does not
  exist.

### Tests

248 of them, up from 185, and no network in any of them. The new ones drive the USM layer
against a fake agent that really verifies the digest and really decrypts the scoped PDU —
including the failures that matter: a wrong authentication passphrase, a wrong privacy
passphrase, an unknown user, a digest that does not match, an unsigned answer to a signed
question, a reply from an hour ago, and a device that reboots mid-conversation.
